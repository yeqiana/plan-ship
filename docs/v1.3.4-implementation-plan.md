# PlanShip v1.3.4 方案、两轮评审与测试验收

## 目标与范围

修复 v1.3.3 的反事实证据拼接风险、HTML 表格保真、图片及占位符碰撞，并增加每个方案的离线大白话主入口。仅修改 `plan-ship`；核心 Skill 仍无 Python/WebCodex/gen-ui 强制运行依赖。

## 实施方案

1. 受控 Python 变异执行器：在临时复制目录替换真实生产源码并运行 pytest，核对被测模块在目标 testcase 内加载的变异 SHA、测试 SHA、真实 JUnit 失败、日志及 run ID/nonce。报告可重跑但不是密码学可信证明；Java 当前无受控适配器时不放行自动验收。
2. 修改最终证据门禁：无记录、记录哈希错误、测试源码改变、运行时加载错模块、报告 run ID/nonce 不匹配均阻断。静态扫描只是结构提示。
3. 改善 HTML 转换：表格代码跨度和转义竖线、图片本地路径安全、消除可碰撞占位符；HTML 原文状态不可丢。
4. `大白话解释/index.html` 列出已登记 MD/HTML 并显示真实状态；`doc_registry.py` 的 `publish`、`sync-html --apply`、`verify` 都纳入。
5. 历史迁移：`sync-html` 默认只预览，`--apply` 安全批量同步；只覆盖登记哈希匹配文件，未知 HTML 立即阻断。

## 评审 R1 — 信任边界

发现风险：单独存在的变异补丁和失败 XML 可以拼接；采取运行时模块 SHA 关联及目标 testcase 实际失败，并明确本地文件仍可伪造。不可声称浏览器页面已经视觉/无障碍验收。

## 评审 R2 — 兼容和恢复

风险：在旧文档目录增加 `index.html` 会影响孤立 HTML 检查和事务回滚；将入口登记 SHA 纳入索引并扩充事务边界，旧缺失入口可在源文档哈希校验后创建。同步过程不能覆盖用户写入，默认只预览。

## 测试与验收

- 实际 pytest 变异失败+恢复绿色、仅改测试预期的失败报告拒绝、错误模块/运行 trace/nonce 拒绝。
- HTML 表格 `A|B`、`A\|B` 的状态保真；图片链接安全与恶意 Markdown 转义；旧占位符文本不变。
- 主入口列全、离线 HTML 正常、未知 HTML 不覆盖、HTML/入口/索引事务故障注入回滚。
- 发行结构、全部旧用例与新增专项分组回归；未执行真实 Codex/Claude 宿主端到端测试时明确标记未验证。
